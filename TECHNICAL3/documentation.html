Intelligent Tutoring System

Our Python program uses case-based reasoning to recommend support for a student who repeatedly makes errors in mathematics. It retrieves a successful past intervention, adapts the feedback, reviews a follow-up result, and saves the new case.

Case base and new problem

Five fictional cases are stored as dictionaries with an ID, problem, solution, and outcome. The problem records the topic, observed errors, grade, and error frequency in five attempts. Solutions contain a teaching strategy, feedback, and practice count. Error labels are entered by a user; the program does not automatically diagnose algebra.

Similarity and retrieval

Score = 100 × (0.30T + 0.45E + 0.15G + 0.10F)

T is 1 for matching topics and 0 otherwise. E is the number of shared error types divided by the number of distinct error types across both cases (Jaccard similarity). G and F each use max(0, 1 − |new − past| / 5) for grade and frequency. These are demonstration weights; error patterns receive the greatest weight. Cases are ranked by score, with ties resolved by case ID.

C01 scores 100 × (0.30 + 0.45 + 0.12 + 0.08) = 95% and is retrieved on the first run.

Adaptation revision and retention

We reuse C01's balance strategy, select feedback for the current errors, and use Grade 8 examples. The higher error frequency raises practice from three problems to four and adds two guided examples. The worked solution subtracts 6 from both sides, then divides by 3 to get x = 4.

A follow-up result of at least 80% marks the intervention successful. A lower result adds two practice problems, capped at ten, and teacher guidance. An unrecorded result remains pending. Only successful cases are eligible for retrieval. The demonstration uses a clearly labelled simulated score of 4/5. Retention writes C06 to JSON; later runs can retrieve it at 100%. Identical profiles with the same outcome are not saved twice.

Run the program

Use python main.py for the demonstration or python main.py --interactive for your own profile and quiz result. No third-party packages are required. Use python main.py --data fresh_cases.json with a new filename to repeat the five-case starting point. Run checks with python -m unittest -v.

Pair reflection

I focused on defining the student profiles and describing the learning errors, while my partner helped implement the similarity calculation and saving process. We worked together on adapting the feedback and checking the program output. One challenge was deciding which attributes should have the greatest influence when comparing a new student with previous cases. We addressed this by giving error patterns the highest weight and using topic, grade level, and error frequency as supporting factors. We learned that case-based reasoning involves retrieving an experience, reusing and revising its solution, and retaining the new case for future use. This activity also showed us why storing a proposed intervention is different from confirming that it successfully helped a student.
